Unreal Engine ProjectS

Impact Reaction Subsystem

I engineered a data-driven Impact Reaction Subsystem that allows designers and technical artists to decouple game logic from visual and physical outcomes. By defining configuration rules inside data assets - covering target materials, gameplay tags, and conditions - the system dynamically triggers context-accurate reactions without hardcoding dependencies.

As demonstrated in the video, the subsystem is invoked directly through the weapon's shoot ability event to evaluate hit data, query the DA_BulletImpacts or DA_Footsteps ruleset, and resolve real-time responses. This modular architecture keeps the codebase clean while giving content creators full flexibility to scale environmental interactions.

Multiplayer RTS Prototype (Weekend Project)

This prototype showcases a fully functional multiplayer Real-Time Strategy (RTS) game developed rapidly over a single weekend. Designed with an authoritative server architecture, it leverages Unreal Engine's robust Gameplay Ability System (GAS) and Attribute Sets to ensure fair, synchronized gameplay for all connected clients. Core mechanics implemented include dynamic unit health, shields, temporary boosting effects, responsive unit movement, and targeted attacking capabilities. The system supports spawning diverse unit types with varying levels and facilitates building upgrades for persistent progression.

Network synchronization is handled server-authoritatively, guaranteeing consistent game state and fairness across all clients. To enhance team identification during gameplay, units dynamically display team affiliation through RGB-colored heads corresponding to their assigned team. While visual effects (VFX) and unit coloration utilize Unreal's visual scripting, all core gameplay logic - including abilities, attributes, movement, combat, spawning, and upgrades - is implemented natively in C++. This C++ foundation utilizes inheritance hierarchies, component-based design, and interfaces to maximize code clarity, reusability, and runtime performance.

Split Screen Fast Prototyping Game

This prototype showcases the core competitive mechanics for a time-based multiplayer game where victory hinges on controlling the highest number of in-game objects by the match's conclusion. Players capture objectives through direct physical contact or by shooting them with projectiles. Success, however, comes at a cost: each capture action depletes the player's health. This health loss is visually represented by the player character shrinking in size. Crucially, falling below a critical health threshold imposes severe gameplay restrictions, disabling the player's ability to capture new objectives or fire projectiles, forcing strategic retreat or resource seeking.

The arena features dynamic environmental systems to enhance tactical depth. Hazardous traps, such as spike fields, rapidly accelerate player health depletion upon contact. Strategic pickups offer temporary advantages, either increasing the player's maximum health (and consequently their size) or enhancing mobility through greater speed, faster rolling, and higher jumps. Team-based paint pools introduce a zone-control element; these only activate when a single player successfully controls both multi-colored foundation cubes beneath a pool. Once active, these pools provide significant tactical advantages, healing players aligned with the controlling team's color while damaging opponents who enter.
